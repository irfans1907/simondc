# Customer

## /customer is a redirect; the real page is /customer/overview
The customer module mirrors the rack module structure: `customer.index` only redirects to `customer.overview`, and the table lives in `resources/js/pages/dynamic/customer/overview/index.tsx`. Routes sit before the `/{parent}/{child}` catch-all, permission group `view-customer-list|manage-customer-list` (GET) and `manage-customer-list` (mutations). **Permission names follow the MENU name, not a guess**: the parent menu row is `Customer List` (id 30), so the DB (and `hasPermissionTo`) uses `view customer list` / `manage customer list` — the `...customer management` names do NOT exist and `hasPermissionTo` throws `PermissionDoesNotExist` (500) on a live DB while tests pass (tests `firstOrCreate` whatever name they use). Same for the page heading/`Head` title: it says "Customer List" to match the breadcrumb. There is intentionally NO `dynamic/customer/index.tsx` (the parent placeholder was deleted; `MenuController::generatePageFile` will silently recreate it if the menu row is edited — it stays unreachable because the real route wins).

## One rack holds at most one customer
`customers.rack_id` is `unique()` + `restrictOnDelete`. `Rack::customers()` is a HasMany used for: the `availableRacks` prop (`Rack::whereDoesntHave('customers')`), the unique rule in `CustomerRequest` (`Rule::unique(...)->ignore($this->route('customer'))`), and a guard in `RackController::destroy` that flashes an error toast (session key `inertia.flash_data`) instead of letting the FK throw a 500. The edit dialog appends the customer's OWN rack to `rackOptions` (its rack is "taken" by itself, so the server no longer lists it as free). Customer CRUD also DRIVES `racks.status`: store marks the rack `Rack::OCCUPIED_STATUS` ('Occupied'), an update that changes `rack_id` frees the old rack and occupies the new one, and destroy frees it (both releases guarded by `whereDoesntHave('customers')`) — `status` is never user input, so it must not be added to forms, RackRequest, or `customerPayload()` in tests.

## Tipe Rak is derived, never stored
The customers table has no tipe_rak column — the controller eager-loads `with('rack:id,rack_code,type,capacity,floor,room')` and the form renders a read-only Input (no `name`) that auto-fills from the selected rack option. Table cells read `customer.rack.type` / `customer.rack.rack_code`. Any rack-type rename/cascade therefore flows to the customer page for free.

## Choice lists are server props, not frontend constants
`Customer` holds the static lists (`CITIES`, `LOCATIONS`, `BUSINESS_STATUSES`, `SERVICE_STATUSES`, `POWER_SOURCES` = `['Single Source', 'Dual Source']` — placeholders until a cities/locations master exists) and the controller ships them as the `filterOptions` prop; `switchOptions` = distinct **`assets.name` (Nama Perangkat)** from the **Switch category + all of its descendants ONLY** (`switchCategoryIds()` delegates to `Category::idsByName()` — Network root assets and sibling sub-categories are deliberately excluded); empty until switch assets are recorded → the Switch select renders disabled with "Belum ada data aset switch". Never hardcode these lists in the TSX. Validation mirrors them with `Rule::in(...)`.

## Panel PDU / MCB Nomor are dependent FK dropdowns (NOT free text)
The old `panel_pdu`/`mcb_number` string columns were dropped and replaced by `panel_asset_id`/`panel_mcb_id` (+ `_2` for Dual Source), FK `restrictOnDelete` into assets/panel_mcbs. **Dropdown chain is Power Source → Panel PDU → MCB**: the Panel PDU select is disabled with "Pilih power source terlebih dahulu" until a power source is picked, and changing the power source resets all four panel/MCB states so no stale pair submits (pair 2 fields only render while `isDual`). `panelOptions` prop = Panel Power-tree assets with nested `mcbs` (each with `taken_by` = customer id); the MCB select filters out slots taken by OTHER customers (`taken_by === null || taken_by === customer?.id`) and resets when the panel changes. Rules live in `CustomerRequest`: asset must be in the Panel Power tree (`Category::idsByName` — a FormRequest cannot share the controller helper, which is why the recursion moved to the model), MCB must belong to the selected asset (`Rule::exists(...)->where('asset_id', ...)`), and an `after()` hook enforces: Dual Source requires pair 2 / Single Source forbits it, both pairs optional while power_source is empty, MCB B ≠ MCB A, and one MCB feeds at most one customer (checked across BOTH columns, ignore-self). Tabel menampilkan pasangan dual digabung di sel yang sama (`"PDU-A + PDU-B"` / `"MCB-01 + MCB-02"`), layout 25 kolom tetap.

## PDU Outlet rak ↔ Power Source: advisory correlation, never blocking
`racks.pdu_outlet_1/2` ("Ada"/"Tidak Ada") stays rack-facility data with NO FK to anything — but a customer's power source implies an outlet need (Single → 1, Dual Source → 2), so `outletShortage(powerSource, rack)` in the customer page flags a shortage: the info line ("PDU Outlet rak: 1 & 2 / 1 saja / tidak ada") and the amber warning render in one block **directly under the Power Source select** (moved from under the rack fields — power source + outlet condition belong together), plus an amber **"PDU Outlet kurang"** badge under the Power Source cell in the table. No power source picked or no rack picked → no warning, and **saving is never blocked** (outlets can be added later). Both `availableRacks` and the eager-loaded `rack` relation therefore include `pdu_outlet_1,pdu_outlet_2` in their column selects — the Edit dialog's appended own-rack fallback must copy them from `customer.rack` too.

## Page conventions (same as rack/asset)
25 columns (No + 23 spec fields + Aksi) with `min-w-[2400px]` so horizontal scroll actually engages; footer `Pagination` renders `PerPageSelector` in one flex row (per-page left, "Showing of {total} total customers" center, links right); search whitelist = all/customer_name/city/location/service_status + `rack_code` via `whereHas` (unknown columns fall back to `all`); navigation uses Wayfinder `.url()` strings (`customerOverview.url()`), never the bare RouteDefinition.
